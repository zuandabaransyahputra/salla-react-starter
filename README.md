# Salla React Starter

A light starter for [Salla](https://salla.sa) storefront themes built with React: TanStack Start
and Vite, server-rendered at the edge by `@salla.sa/twilight-theme-engine`, Arabic and RTL first.

It is Salla's official React starter cut down to a clean base, plus the tooling you end up
writing anyway: a rename script, RTL-correct UI primitives, a visual QA matrix, Lighthouse runs and
a locale check. Every page renders with the engine's default components, so you start from a
working store and replace only what your design needs.

**Who it is for:** developers building a Salla Twilight theme for a client or for the Salla Theme
Store who want a typed, tested base without inheriting someone else's design.

## Features

- **Engine defaults everywhere.** Home, product, listing, cart, blog, account, header and footer
  come from the engine and its generated routes. Override one piece at a time (see
  [docs/engine-forks.md](docs/engine-forks.md)).
- **shadcn/ui primitives on theme tokens** in `app/components/ui`: Button, Input, Textarea,
  Select and Dialog (Radix via `radix-ui`, variants via `class-variance-authority`), with a
  `cn()` helper that merges the theme's token classes.
- **Theme tokens** (`app/styles/01-settings/tokens.scss`): surface, ink, line and accent colours
  that follow the merchant's primary colour, plus dark values behind a `.dark` class.
- **RTL first.** Logical Tailwind utilities only, a test that fails on `ml-*`/`left-*`/`text-right`
  in components, Arabic-capable font fallbacks, and [docs/rtl.md](docs/rtl.md).
- **An example home block** (`home.example-banner`) wired through `twilight.json` and
  `registerHomeComponents`, to copy for your own blocks.
- **Tooling:** `new-theme` (name and identity), `qa` (screenshots: desktop/phone × ar/en ×
  light/dark, with overflow and console-error checks), `lighthouse` (mobile and desktop, with the
  failing audits listed), `check:locales`, `check:manifest`.
- **CI** on GitHub Actions: install, build, typecheck, test, manifest and locale checks.

## Quick start

You need pnpm 10 and Node.js 22 (22.22.2 or later), 24 (24.15.0 or later) or 26+.

```bash
git clone https://github.com/zuandabaransyahputra/salla-react-starter my-theme
cd my-theme && rm -rf .git && git init
pnpm install
pnpm new-theme --name-en "Mawj" --name-ar "موج" \
  --repo https://github.com/<you>/mawj --email you@example.com
pnpm build && pnpm typecheck && pnpm test
```

Point the dev server at a store, then run it:

```bash
salla theme dev   # Salla CLI: writes .env with VITE_STORE_DOMAIN and VITE_TWILIGHT_URL
pnpm dev          # open http://localhost:5173/ar
```

`VITE_STORE_DOMAIN` is the store whose data the dev server renders (create a demo store in the
Salla Partners Portal). `VITE_TWILIGHT_URL` is the fallback twilight SDK build, used only when the
store's settings don't pin a release (`theme.twilight.version`). You can also scaffold a theme
from Salla's own template with `npx @salla.sa/cli@beta theme create`.

The whole path from a new theme to a review submission is in [docs/workflow.md](docs/workflow.md).

## Scripts

| Script                       | Description                                                          |
| ---------------------------- | -------------------------------------------------------------------- |
| `pnpm dev`                   | Start the Vite dev server (workerd)                                  |
| `pnpm build`                 | Production build (also generates `app/routeTree.gen.ts`)             |
| `pnpm preview`               | Serve the production build                                           |
| `pnpm typecheck`             | TypeScript type checking (run `pnpm build` once first)               |
| `pnpm test`                  | Run the test suite (Vitest)                                          |
| `pnpm check:manifest`        | Validate `twilight.json`: duplicate ids, missing options, bad values |
| `pnpm check:locales`         | Fail when `locales/ar.json` and `locales/en.json` differ in keys     |
| `pnpm new-theme`             | Set the theme's name and identity, fresh block keys                  |
| `pnpm qa [dir] [shots]`      | Screenshot matrix with overflow and console-error report             |
| `pnpm lighthouse <url> [...]`| Lighthouse, mobile and desktop, on a home URL and paths on it        |

`qa` and `lighthouse` drive headless Chrome (Node 22's built-in WebSocket, no extra
dependencies). Set `CHROME_PATH` when Chrome is not in the default macOS location. `qa` works
against the dev server or any storefront: `QA_ORIGIN=https://<store-domain> pnpm qa`.

## Project layout

```text
app/routes/__root.tsx     the document shell: <html lang dir>, TwilightProvider, dev tools
app/routes/*.tsx          generated by the engine (`// @auto-generated`); edit one to own it
app/routes.ts             routes at new paths
app/router.tsx            home blocks (registerHomeComponents) and hook slots
app/components/ui/        Button, Input, Textarea, Select, Dialog
app/components/home/      the example home block
app/hooks/index.tsx       content for the engine's hook slots
app/lib/                  cn(), theme id, helpers
app/styles/               Tailwind entry, tokens, and the baseline styles for engine components
locales/{ar,en}.json      theme translations
twilight.json             theme manifest: settings, home blocks, features
docs/                     workflow, RTL rules, engine forks
scripts/                  new-theme, qa, lighthouse, check-locales
```

## RTL

Arabic is the default language of most Salla stores, so the starter is built right-to-left first:

- The engine writes `lang` and `dir` on `<html>` from the URL (`/ar` → `rtl`).
- Components use logical utilities (`ms-*`, `pe-*`, `start-*`, `text-start`, `rounded-s-*`);
  `tests/styles/logical-classes.test.ts` fails on physical ones unless they sit behind an explicit
  `ltr:`/`rtl:` variant.
- Things that don't mirror by themselves are handled in the primitives: the Dialog's centring
  translate flips with the direction, the close button and the Select check mark sit at the end
  edge, and Radix reads `dir` for keyboard and popover alignment.
- The font stack starts with the store's font (`--font-main`, `--font-ar` in RTL) and falls back to
  system fonts that cover Arabic script.

Read [docs/rtl.md](docs/rtl.md) before writing your first component.

## Deployment

Salla builds and publishes your theme on its own infrastructure: push to your theme repository and
the platform takes it from there. No deploy configuration, credentials or server runtime settings
ship with this starter.
